### 🧪 Test 文件与测试规范（适用于所有测试相关任务）

#### ✅ 基本原则

- 所有测试必须基于**真实逻辑场景**，**不得停留在代码表层结构的“假测试”**（如仅覆盖接口调用、不验证业务逻辑）；
- 测试必须验证以下内容之一，才视为有效：
  - 实际状态变化（如状态管理、后端数据写入）；
  - 接口调用完整性与响应结构；
  - 权限判断 / 分支逻辑是否按预期执行；
  - 渲染输出是否符合业务预期；

#### ❌ 明确禁止

- 禁止提交无实际断言、无状态验证的“假测试”；
- 禁止以提高覆盖率为目标编写无效测试逻辑；
- 禁止保留未启用、未被引用的 test 文件；

#### 🔁 清理机制

- **测试完成后，必须手动清理：**
  - 所有临时 test 文件；
  - 无需保留的 mock 文件、断言工具、测试数据等；
- 若测试模块与原模块合并，请统一收敛至 `/__tests__` 或 `*.spec.tsx`、`*.test.ts` 结构中，**避免结构混乱**；
- 请勿将测试逻辑遗留于业务模块内部（如 `src/module/Foo.tsx` 中残留 `test(...)` 函数）；

#### 🔐 冻结与交付要求

- 对已验证通过的逻辑模块，请添加注释标记：
  ```ts
  // ✅ TESTED: 已完成真实业务验证，测试时间 2025-08-06
  // 🔒 LOCKED: 如需修改请重新创建测试模块，不得修改原 test 框架
